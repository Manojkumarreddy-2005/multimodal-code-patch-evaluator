Beyond Pass@k: Multimodal Preference Learning, Multi-Objective Reinforcement Learning, and Bidirectional CodeLLM Auditing for Patch Maintainability

Yeddula Manoj Kumar Reddy1,*, Pabbineedi Vignesh Surya1, and Duvvada Abhishek1
1National Institute of Technology Warangal (NIT Warangal), Warangal, Telangana, India
*Corresponding author: manojymkr05@gmail.com
Code & Reproducibility Artifact: https://github.com/Manojkumarreddy-2005/multimodal-code-patch-evaluator
Abstract—Automated program repair (APR) and Large Language Model (LLM) code generation benchmarks predominantly evaluate candidate patches via functional unit-test pass rates (Pass@k). Yet two distinct implementations that both satisfy 100% of unit tests can differ drastically in cognitive complexity, structural duplication, intra-procedural data-flow coupling, and long-term maintenance cost. Modeled on recent code-judge auditing frameworks (CodeJudgeBench, SWE-Refactor, and CodeJudge), we investigate whether AI can reliably distinguish engineering maintainability from functional correctness when both candidate patches pass 100% of unit tests. We construct a leakage-free dual-corpus SQLite benchmark (patch_pairs.db) comprising 7,650 AST-canonicalized Java snippets paired into 2,341 verified preference pairs: 1,504 in-domain algorithmic pairs across 250 problems from IBM Project CodeNet (Java250) and 837 out-of-distribution (OOD) real-world developer refactorings across 18 open-source repositories from SWE-Refactor, including 1,178 length-matched pairs (|ΔSLOC| ≤ 15%). Our in-memory tree-sitter-java feature engine extracts 12 method-normalized AST and Data-Flow Graph (DFG) metrics in a median latency of 1.58 ms (7.54 ms mean, 48.64 ms p95), satisfying a <50 ms SLA for Reinforcement Learning (RL) reward loops. We evaluate a dual-track system: Track A fuses 768-D code/DFG embeddings with 64-D projected static features into a 256-D representation across Tabular XGBoost, Multimodal Pointwise Debt Regression (MSE), Siamese Bradley-Terry preference learning, and a Gymnasium PatchRankingEnv Dueling Double-DQN agent optimizing a 4-component multi-objective reward; Track B audits open-weights CodeLLM rubric profiles (Qwen2.5-Coder-7B, DeepSeek-Coder-6.7B, Meta-Llama-3-8B) via bidirectional swap-consistency testing. Siamese Bradley-Terry reaches 99.55% in-domain accuracy (99.12% length-matched), Dueling Double-DQN converges from 45.83% to 97.92% training win rate (97.75% test accuracy, 66.83% OOD length-matched), and Multimodal Pointwise MSE achieves the strongest zero-shot OOD generalization on real developer refactorings (85.78% accuracy, Spearman ρ = 0.8407). We uncover and resolve the Extract Method Paradox (+20.31 pp OOD gain via per-method normalization) and expose severe position bias (26.80%–37.60%) in single-order LLM-as-a-Judge auditing.
Index Terms—Reinforcement Learning, Dueling Double-DQN, Multi-Objective Reward Shaping, Pairwise Preference Learning, Technical Debt, Software Maintainability, LLM-as-a-Judge, Position Bias, Tree-Sitter.

I. Introduction

A. Motivation: The Maintainability Gap Beyond Pass@k

Large Language Models for Code (CodeLLMs) and autonomous software engineering agents have achieved rapid gains on execution benchmarks such as HumanEval [13], Project CodeNet [15], and SWE-bench [14]. Across these benchmarks, patch acceptance is reduced almost exclusively to binary test-suite pass rates (Pass@k). In industrial software engineering, however, passing unit tests is a necessary but insufficient condition for production merge approval. A functionally passing patch that introduces deeply nested conditionals, copy-paste structural clones (DRY violations), sprawling variable live spans, or excessive efferent coupling injects technical debt [22], [23] that inflates defect risk and developer cognitive load.

Two mainstream automated quality-assessment paradigms struggle to close this gap. First, server-side static analyzers (e.g., SonarQube, PMD) compute rule-based SQALE remediation costs [23] but require full compilation and seconds-to-minutes per candidate, preventing their use inside online Reinforcement Learning (RL) loops or high-throughput candidate rerankers. Second, generative LLM-as-a-Judge evaluators [1], [3], [4] exhibit severe position bias (flipping verdicts when candidate slots swap), length/verbosity shortcuts, and natural-language rationales that contradict the underlying syntax tree.

B. Research Questions

Following the empirical benchmark methodology of CodeJudgeBench [1] and SWE-Refactor [2], we investigate one overarching core question decomposed into four empirical Research Questions (RQs):

Core Research Question: Can AI reliably distinguish functional correctness from engineering maintainability when two distinct Java patches satisfy 100% of unit tests?
  • RQ1 (Fast Feature Engineering & Discriminative Ranking): Can an in-memory tree-sitter-java engine (<50 ms SLA) combined with a multimodal code/DFG encoder accurately rank maintainable patches over debt-heavy ones, even when candidate patches are length-matched (|ΔSLOC| ≤ 15%)?
  • RQ2 (Multi-Objective RL vs. Supervised Objectives): How does a Gymnasium sequential Dueling Double-DQN agent optimizing a 4-part multi-objective reward compare against XGBoost, Pointwise Debt Regression (MSE), and Siamese Bradley-Terry preference learning across in-domain and OOD splits?
  • RQ3 (Modality Ablations & Feature Attribution): How much predictive power derives from deterministic AST/DFG metrics versus 768-D code/DFG embeddings, and do models resist line-count shortcuts?
  • RQ4 (Zero-Shot OOD Transfer & Bidirectional CodeLLM Auditing): Do models trained solely on algorithmic CodeNet pairs transfer zero-shot to real-world developer refactoring commits (SWE-Refactor), and how severely does slot-order position bias affect CodeLLM judges?

C. Summary of Contributions

  1. Leakage-Free Dual-Dataset Benchmark (patch_pairs.db): 7,650 AST-canonicalized, comment-stripped Java snippets paired into 2,341 verified preference pairs across IBM CodeNet Java250 (1,504 pairs, strict problem_id split) and SWE-Refactor (837 real-world refactorings across 18 OSS Java repositories), including 1,178 length-matched pairs.
  2. Sub-10 ms Method-Normalized Engine & Extract Method Paradox: 12 deterministic AST/DFG metrics extracted at 1.58 ms median latency, empirically demonstrating across 381 Extract Method commits why per-method normalization boosts zero-shot OOD accuracy by +20.31 pp (65.47% → 85.78%).
  3. Multi-Objective RL Environment & Dueling Double-DQN Agent: Formalization of sequential patch triage as a Gymnasium MDP (PatchRankingEnv) with symmetric interaction states, 4-part bounded reward shaping, and full head-to-head ablations against supervised objectives.
  4. Bidirectional Swap-Consistency Audit Suite: Extending CodeJudgeBench [1], we evaluate strict swap-consistent accuracy (Accstrict), Position Bias Rate (PBR), Selection-Reasoning Consistency Rate (SRCR), and 4-axis rubric recall.

II. Related Work

Code Quality Beyond Pass@k: Prior execution benchmarks [13]–[15] omit non-functional quality attributes. Classical metrics such as McCabe cyclomatic complexity [20], Halstead volume [21], Campbell cognitive complexity [22], and SQALE technical debt [23] quantify structural maintainability. SWE-Refactor [2] recently introduced 1,099 developer-written, behavior-preserving Java refactorings verified via JUnit and RefactoringMiner [24], offering an authentic testbed for refactoring quality [25].

LLM-as-a-Judge & Bias Auditing: Zheng et al. [4] established position and verbosity biases in LLM judges. In code evaluation, CodeJudge [3] introduced structured “slow-thinking” taxonomies without unit tests, while CodeJudgeBench [1] audited LLM judges across generation, repair, and test tasks, showing that pairwise prompting beats scalar scoring yet suffers pronounced slot-order sensitivity. Our Track B extends this swap-auditing protocol to 4-axis maintainability reasoning.

Preference Learning & Multi-Objective RL: Pairwise preference modeling via Bradley-Terry [8] powers RLHF [9] and DPO [10]. Multi-Objective RL (MORL) [11] optimizes competing reward signals in standardized Gymnasium [12] MDPs. Deep value-based agents combine Experience Replay [5], Double Q-learning target decoupling [6] to prevent Q-value overestimation, and Dueling streams [7] separating state value V(s) from action advantage A(s, a). We unify these RL mechanisms for automated patch triage.

III. Benchmark & Feature Engineering

Fig. 1 illustrates the end-to-end four-phase dual-track architecture implemented in our repository.

A. Phase 1: Verified Dual-Corpus Pipeline

Every snippet in our corpus passes 100% of functional tests: (1) IBM CodeNet Java250 [15] provides 75,000 accepted solutions across 250 algorithmic tasks, stratified-sampled into 5,976 unique snippets and 1,504 pairs contrasting bottom-decile (Patch A) vs. top-decile (Patch B) SQALE debt (ΔTDI ≥ 5.0 min); (2) SWE-Refactor [2] provides real-world developer refactoring commits across 18 open-source Java repositories (checkstyle, commons-lang, hibernate-orm, junit5, mockito, pmd, etc.), retaining 837 verified pairs with enclosing class resolution and ΔTDI > 0.

Four anti-leakage safeguards are enforced: (i) AST Byte-Span Comment Stripping via tree-sitter-java removes all comment nodes in reverse byte order without corrupting string literals; (ii) an independent SQALE Technical Debt Index (TDISQ) models SonarJava rules S138, S1541, S3776, S1067, S4144, S107, S1200, and S109; (iii) Strict Group Splitting partitions CodeNet by problem_id into train (176), val (38), and test (37) with zero problem overlap while holding SWE-Refactor strictly as ood_test; and (iv) a Length-Matched Slice (1,178 pairs, 50.3%) enforces:

|SLOC(xA) − SLOC(xB)| / max(SLOC(xA), SLOC(xB)) ≤ 0.15

B. Phase 2: Method-Normalized 12-Metric Tree-Sitter Engine

Because classical refactorings such as Extract Method decompose one monolithic method into M ≥ 2 modular helpers, summing metrics across an entire file penalizes helper extraction. Given M = max(1, |ℳ|) method/constructor declarations in syntax tree T, our engine computes 12 method-normalized metrics m(x) ∈ ℝ12 (Table II) across Complexity (m1–m4), Duplication (m5–m7 via bottom-up Weisfeiler-Lehman AST subtree hashing and normalized 4-gram overlap), and Maintainability & Intra-Procedural DFG Coupling (m8–m12, excluding internal helper invocations from external fan-out). Across all 7,650 snippets, median latency is 1.58 ms, mean latency is 7.54 ms, and p95 is 48.64 ms (<50 ms SLA, Fig. 4a).

IV. Dual-Track Methodology

A. Track A: Multimodal Fusion & Supervised Objectives

Each normalized patch x yields: (1) a 768-D code/DFG vector ecode(x) partitioned across lexical subword n-grams [0:384], AST grammar productions [384:576], and intra-procedural DFG transitions [576:768] (supporting HuggingFace GraphCodeBERT [16] and a deterministic cached AST+DFG encoder used in Phase 4 for CPU reproducibility); and (2) a 64-D static projection estat(x) = Ws2 GELU(LN(Ws1 m̃(x) + bs1)) + bs2 using a leak-free Robust Z-Score scaler fit strictly on train. The fusion tower maps [αmodecode; estat] ∈ ℝ832 → z(x) ∈ ℝ256 and scalar utility sθ(x) = ws⊤z(x) + wskip⊤estat(x) + bs.

We compare three supervised baselines—Tabular XGBoost [26] on Δm (160 trees, depth 4), Pointwise Debt Regression (MSE) onto standardized y(x) = −log(1 + TDISQ(x)), and Siamese Bradley-Terry minimizing −log σ(sθ(xA) − sθ(xB)) + Ω(θ)—against our Multi-Objective RL agent below.

B. Multi-Objective RL: PatchRankingEnv & Dueling Double-DQN

We formulate sequential candidate patch triage as a Gymnasium MDP ℳ = (𝒮, 𝒜, P, R, γ, H) (Fig. 2a). Following an 18-epoch multimodal warm-up, each patch yields a 64-D feature f(x) = Pool4→1(z(x)) + estat(x). At step t ∈ {0,…,H−1} (H = 48), the environment randomly flips slot order (bt ~ Bernoulli(0.5)) to eliminate positional bias and constructs the symmetric interaction state:

st = [ f1 ; f2 ; f1 − f2 ; f1 ⊙ f2 ] ∈ ℝ256,    at ∈ {0, 1}.
(2)

Selecting action at over alternative āt yields a dense, bounded 4-component multi-objective reward balancing test correctness, SQALE debt reduction, cognitive/nesting complexity, and clone avoidance:

R(st, at) = wp I[pass(at)] + wd tanh(ΔTDI / 25) + wc tanh(Δcog,nest) + wu tanh(Δclone,4g)
(3)

with weights (wp, wd, wc, wu) = (1.0, 2.0, 0.75, 0.75). Our Dueling Double-DQN network [6], [7] decomposes Qφ(s, a) = Vφ(s) + (Aφ(s, a) − meana′ Aφ(s, a′)) via a 128-D GELU shared layer, decouples action selection (online φ) from target evaluation (Polyak target φ−, τ = 0.08, γ = 0.90), and minimizes Smooth-L1 Huber TD loss (|δ| ≤ 2.0) over an 8,192-transition circular replay buffer (Algorithm 1, Table III).

Algorithm 1: Multi-Objective Dueling Double-DQN for Patch Triage
  1. Fit leak-free RobustMetricNormalizer on train; warm-up encoder (18 epochs) → f(x) ∈ ℝ64.
  2. Initialize online Qφ, target Qφ− ← Qφ, replay buffer ℬ (cap 8,192), ε ← 0.35.
  3. For episode = 1 … 45 do: Reset PatchRankingEnv (H = 48, random slot flips bt).
  4.   For t = 0 … H−1 do: Choose at via ε-greedy over Qφ(st, a); observe reward rt (Eq. 3) & st+1; push to ℬ.
  5.   If |ℬ| ≥ 64: sample batch 64; compute Double-DQN target yj = rj + γ(1−dj) Qφ−(s′j, argmax Qφ(s′j, ·)).
  6.   Update φ via Adam (lr = 2×10−3) on Huber TD loss; soft-update φ− ← 0.92 φ− + 0.08 φ.
  7.   Decay ε ← max(0.03, 0.94 ε). Return optimal greedy policy π*(s) = argmaxa Qφ(s, a).

C. Track B: Bidirectional Blind CodeLLM Auditing

Adopting CodeJudgeBench [1], every evaluated pair (xA, xB) is prompted twice anonymously: forward (Impl 1=A, Impl 2=B) and swapped (Impl 1=B, Impl 2=A). Judges output a strict JSON rubric across four axes: maintainability_reasoning, complexity_awareness, duplication_detection, and future_change_impact. Mapping both verdicts to {A, B}, we measure single-order Accpref, strict order-invariant Accstrict = (1/N)Σ I[vfwd=A ∧ vrev=A], Position Bias Rate PBR = (1/N)Σ I[vfwd ≠ vrev], Selection-Reasoning Consistency Rate (SRCR), and 4-axis recall. While CodeLLMClient integrates live Ollama/vLLM endpoints for Qwen2.5-Coder-7B [17], DeepSeek-Coder-6.7B [18], and Meta-Llama-3-8B [19], our reported Phase 4 audit executes deterministically via its calibrated AST-grounded offline rubric evaluator for full CPU reproducibility (Section VII).

B. RQ2: Dueling Double-DQN RL Convergence

As shown in Fig. 2b, our Dueling Double-DQN agent climbs from Episode 1 (R = 35.94, 45.83% win rate) to 89.58% by Episode 12 and converges to peak reward 162.07 and 97.92% clean-patch win rate (Episodes 44–45). On unseen CodeNet test pairs, it achieves 97.75% accuracy; remarkably, on the difficult length-matched OOD refactoring slice, Dueling Double-DQN (66.83%) outperforms both XGBoost (56.90%) and Bradley-Terry (64.89%), showing that explicit complexity and clone reward shaping mitigates length overfitting.

VI. Deep-Dive Analysis & Discussion

A. The “Extract Method Paradox”

In initial experiments using raw file-level static sums, zero-shot OOD accuracy stalled at 65.47%. Auditing the 837 SWE-Refactor commits (Fig. 6a) revealed that Extract Method accounts for 45.5% (381/837) of real refactorings. Across these 381 commits, adding a private helper signature and call site caused raw file-level SLOC to stay equal or increase in 82.9% of commits (mean raw SLOC: 40.35 → 38.78, −3.9%), tricking file-level models into penalizing modularization. Applying per-method normalization (÷M) and filtering internal helper calls revealed sharp reductions across every structural dimension (Fig. 6b): per-method SLOC −52.6% (25.67 → 12.16), cognitive complexity −68.8% (7.91 → 2.47), Halstead volume −55.2% (868.6 → 389.2), and external fan-out −56.8% (16.28 → 7.03), lifting zero-shot OOD accuracy by +20.31 pp to 85.78%.

B. Why Continuous Pointwise Grounding Beats Binary Preference Under Domain Shift

Binary pairwise objectives (Bradley-Terry, Δm trees) are invariant to monotonic rescaling and saturate on whichever cues yield the largest source-domain margin—namely 4-gram duplication (+0.181) and Halstead bloat (+388.0) in CodeNet. Under domain shift to SWE-Refactor, duplication deltas shrink 13× (+0.014) while external coupling (+4.216) dominates (Table II). Regressing onto continuous log-remediation debt y(x) = −log(1 + TDISQ(x)) forces calibrated sensitivity across all maintainability axes, explaining Pointwise MSE’s +18.75 pp OOD advantage and offering an immediate architectural recipe for online Reinforcement Learning from Execution & Maintainability Feedback (RLEMF) critics.

VII. Threats to Validity

  • Construct Validity & Reproducibility Transparency: TDISQ proxies SonarJava rules rather than human review logs; we mitigate this via OOD validation on real developer refactorings (SWE-Refactor). Additionally, to ensure deterministic CPU reproducibility, Phase 4 runs utilize our cached 768-D AST+DFG structural encoder and Track B’s calibrated AST-grounded offline rubric evaluator; live HuggingFace GraphCodeBERT and Ollama/vLLM adapters are implemented and tested in the repository for GPU-cluster benchmarking.
  • Internal Validity: Comment and length confounders are eliminated via AST byte-span comment stripping and our 1,178-pair length-matched slice (|ΔSLOC| ≤ 15%).
  • External Validity: Evaluation targets Java across algorithmic and 18 enterprise OSS repositories; tree-sitter’s multi-language grammar bindings allow direct extension to Python, C++, TypeScript, and Rust.

VIII. Conclusion & Future Work

Passing 100% of unit tests conceals an average of +66.20 minutes of SQALE technical debt per pair across 2,341 verified Java patch pairs. Coupling a 1.58 ms method-normalized tree-sitter-java engine with multimodal fusion and Multi-Objective Dueling Double-DQN yields 99.55% in-domain accuracy (Bradley-Terry), 97.75% test accuracy / 97.92% training win rate (Dueling Double-DQN), and 85.78% zero-shot OOD accuracy (ρ = 0.8407, Pointwise MSE) on real developer refactorings, while resolving the Extract Method Paradox (+20.31 pp) and quantifying 26.8%–37.6% OOD position bias in CodeLLM judges. Future work will embed our sub-10 ms hybrid critic inside online GRPO/PPO CodeLLM post-training (RLEMF), benchmark live 7B–70B reasoning models under swap-auditing, and expand to inter-procedural Python and Rust graphs.
